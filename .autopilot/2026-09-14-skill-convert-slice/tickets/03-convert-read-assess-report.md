**Требования:** R04, R05, R07, R08, R09, R11, R18i, R20i
**Blocked by:** 02

**Волна:** 2
**Status:** ready

## Что должно заработать

```
uv run agent-skill-adapter convert <папка-скилла> \
  --source anthropic/claude-code@2.1.0 --target google/antigravity@2.0.0
```

читает папку скилла, находит в ней ключи frontmatter, папки бандла и объявленные события
hooks, спрашивает у описаний сред про каждое найденное свойство и отдаёт машиночитаемый
отчёт в стандартный вывод, читаемый человеком — в поток ошибок, и код возврата.

Ничего не пишется на диск: запись — следующий таск.

## Из брифа, дословно

> «одна папка skill → чтение (FR-13,15,16) → оценка по specs/ (FR-20)»
> «отчёт + код возврата»
> «`unknown` по открытой спецификации (allowed-tools, file-references) — отказ… `unknown`-расширение Claude Code (model, hooks, user-invocable) — перенос с потерями: код 1, запись в отчёт, ничего не теряется молча»

## Разделы спецификации

Истории 3–4, 7–10, 13–15; Решения §«Словарь оценок», §«Вывод по файлу», §«Правило сборки»,
§«Версии сред», §«Отчёт», §«Один модуль, не пакет»; Границы и швы.

## Что переиспользуется, а не пишется заново

`envspec.loader.select` и `base_specs` — выбор описания по версии. `envspec.gaps.compare`
уже отдаёт по каждой записи `outcome` **и** `origin` — ровно то, чего требует таблица сборки.
Отображение «что лежит в папке скилла → id записи» уже написано в
`.autopilot/reports/pr48-real-skills-probe.py`; оттуда его и брать, доведя до вида,
который переживёт ревью.

## Критерии приёмки

- [ ] `convert(skill_dir, source, target, *, out=None) -> Conversion` — единственный шов;
      тесты ходят через него, на крошечных описаниях и временной папке
- [ ] Таблица сборки работает: `unknown`+`specification` → код 3, `unknown`+`extension` → код 1,
      `missing` → код 1, всё воспроизводится → код 0
- [ ] Свойство, которого нет ни в одном описании, попадает в отчёт со своим `found_as`
      и оценкой «неизвестно» — молча не пропадает
- [ ] Структурная поломка (нет `SKILL.md`, битый YAML, дублирующийся ключ, BOM, оборванные
      разделители) даёт код 6 и объяснение, что не так и где; машиночитаемый отчёт выпущен всё равно
- [ ] Версии сред не заданы или вне диапазона — код 3, а не догадка
- [ ] В стандартный вывод не попадает ничего, кроме JSON отчёта; `--report FILE` уводит его в файл
- [ ] Поля отчёта — те, что названы в спецификации, `report_schema` первым
- [ ] Отчёт по непереносимому hook называет три обхода текстом (тело скилла, pre-commit/CI,
      ближайшее событие) и не выбирает между ними
- [ ] `make check` зелёный; `convert.py` не импортирует сеть
