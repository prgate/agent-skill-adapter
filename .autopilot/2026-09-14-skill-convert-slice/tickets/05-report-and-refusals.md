# 05 — Отчёт называет пропущенное, отказ не спорит с вердиктом

**Требования:** R08, R09.1, R11, R11.1 (находки ревью + расхождение, найденное слепой приёмкой)
**Blocked by:** 04
**Зона:** `src/agent_skill_adapter/convert.py`, `src/agent_skill_adapter/cli/main.py`, `tests/unit/test_convert.py`
**Волна:** 4
**Status:** ready

## Что должно заработать

Два обещания конвертера, которые сейчас держатся не везде: «ничего не теряется молча»
и «ответ — это код возврата». Ревью нашло восемь мест, где они провисают. Ни одно
не блокировало сдачу по отдельности; вместе они и есть то самое обещание.

## Из брифа, дословно

> «отчёт + код возврата»
> «`unknown`-расширение Claude Code (model, hooks, user-invocable) — перенос с потерями: код 1, запись в отчёт, ничего не теряется молча»

## Критерии приёмки

Отчёт называет то, что пропустил:
- [ ] Совет-обход следует из того, что найдено в папке скилла, а не из наличия записи
      в сравнении: hook-событие, которого нет ни в одном описании, получает свои строки
      `advice`, а не пустоту (`convert.py:285`)
- [ ] `hook.decision.block` называет все события, из-за которых появился, либо не называет
      ни одного — сейчас при двух объявленных берётся `found_as` первого (`convert.py:266`)
- [ ] Папка, которой в описании цели нет места, — названный факт, а не отсутствие строки
      в `written`: «не собрали, некуда» и «не дошли руки» должны различаться (`convert.py:397`)

Отказ не спорит с вердиктом:
- [ ] Одинаковые по природе отказы обращаются с вердиктом одинаково: выход за `out`
      сейчас уходит с кодом 3 и затирает вердикт таблицы, а столкновение — сохраняет
      (`convert.py:487`)
- [ ] Сопоставление «код отказа → вердикт» — явное отображение, а не обратный проход
      по `EXIT_CODE.items()`, который молча держится на уникальности кодов (`convert.py:670`)
- [ ] `--report` в несуществующую папку выходит сообщением и кодом, а не трассировкой
      (`cli/main.py:73`)

Расхождение слепой приёмки — чтение заголовка не доделано до FR-15/FR-16:
- [ ] Якоря и алиасы YAML отвергаются: сейчас `name: &a x` / `description: *a` принимаются
      молча и дают exit 0, хотя FR-15 говорит «только YAML, без якорей и алиасов»
- [ ] У заголовка есть предел на размер и на глубину: сейчас 10-мегабайтный frontmatter
      разбирается без отказа (FR-15)
- [ ] Отсутствие обязательного поля — структурная поломка: сейчас `SKILL.md` без
      `description` даёт exit 0 «clean», хотя оба описания помечают поле Required (FR-16)
- [ ] `--specs` по умолчанию не делает запуск из чужой папки похожим на настоящий отказ:
      сейчас запуск не из корня репозитория даёт exit 3 «cannot read the environment
      descriptions under specs» — тот же код, что и отказ по `unknown`. Нечитаемые описания
      это не «сведений недостаточно про скилл», а «мы не смогли прочитать свои же файлы»

Тесты, которых нет:
- [ ] Один тест через `CliRunner`: в stdout только JSON, `--report FILE` уводит его в файл.
      Это граница доверия, и ломается она молча
- [ ] Три отказа разбора получают свой случай в уже существующем `BROKEN`: файл без
      ведущего `---`, frontmatter не-отображением, не-UTF-8 (`convert.py:191`)
- [ ] Тест на путь за пределами `out` называет код, которым отказ выходит, а не `!= 0`
      (`test_convert.py:412`)
- [ ] `make check` зелёный
