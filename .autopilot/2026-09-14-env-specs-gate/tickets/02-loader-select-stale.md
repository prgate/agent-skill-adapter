# 02 — Выбор описания по версии и проверка устаревания

**Требования:** R05, R08, R17, R22, R29
**Blocked by:** 01
**Зона:** `src/agent_skill_adapter/envspec/loader.py`, `tests/unit/test_envspec_loader.py`
**Волна:** 2
**Status:** ready

## Что должно заработать

Загрузчик умеет работать с набором описаний, лежащих рядом.

- `load_all(root) -> list[EnvSpec]` — читает все описания из дерева `specs/`.
- `select(root, vendor, environment, version) -> EnvSpec` — возвращает единственное описание,
  чей `version_range` покрывает заданную версию. Ни одного подходящего — `SpecNotFound`.
  Больше одного — `AmbiguousSpec`, и в сообщении перечислены все подходящие файлы: правило
  выбора ещё не объявлено (§5 PRD), поэтому «берём первое» запрещено. Ни одного подходящего —
  `SpecNotFound` с заявленной версией и перечнем объявленных диапазонов; ближайшее описание
  не подставляется (FR-4).
- `is_stale(spec, today) -> bool` — устарело, если `discrepancies` непусто **или**
  `today - checked_at > stale_after_days`. Второе работает без сети и без запуска сверки.
- Отказ на устаревшем описании даёт `select()`, поднимая `StaleSpec`. Обойти можно только явным
  `allow_stale=True` — он существует ради воспроизведения прошлого переноса (FR-9) и сам
  по себе ничего не разрешает.
- `EnvSpec.capability(id) -> Support` — записи нет → `Support.UNKNOWN`. Никогда `UNSUPPORTED`.

Сравнение версий — своё, по `version_range` вида `">=2.1.0,<2.2.0"`. Новых зависимостей не добавлять.

## Из брифа, дословно

> «Описания разных версий среды хранятся рядом, каждое со своей датой проверки. Новая версия
> не затирает предыдущую» (FR-5)
> «Если входным данным соответствует несколько описаний… адаптер отказывается переносить
> и перечисляет подходящие описания» (FR-5)
> «Свойство, которого нет в описании, считается неизвестным, а не поддерживаемым» (FR-12)
> «Устаревшим считается описание с записанным расхождением, а также описание, у которого дата
> проверки старше объявленного в нём срока, даже если сверка ни разу не запускалась» (FR-9)

## Разделы спецификации

Истории 5–10, 21. Решения §«Раскладка», §«Устаревание», §«Свойство, которого нет в описании».

## Критерии приёмки

- [ ] `select` находит единственное подходящее описание по версии
- [ ] Две версии одной среды рядом: `select` возвращает ту, чей диапазон покрывает запрошенную
- [ ] Два описания с пересекающимися диапазонами → `AmbiguousSpec` с перечнем обоих путей
- [ ] Версия вне всех диапазонов → `SpecNotFound`, в сообщении — заявленная версия и все диапазоны
- [ ] `select()` на устаревшем описании поднимает `StaleSpec`; с `allow_stale=True` возвращает его
- [ ] `is_stale` = True при непустых `discrepancies`; = True по дате при пустых; = False у свежего
- [ ] `capability()` на отсутствующем `id` возвращает `UNKNOWN`
- [ ] Ни один модуль, кроме `freshness`, не импортирует сеть (проверяется тестом по исходникам)
- [ ] `make check` зелёный
