## Правила проекта, которые нельзя вывести из кода

- Python 3.10, uv-окружение. Зависимости: pydantic, pyyaml, typer, rich.
  **Новая зависимость — CFP Level 3: не ставить, вернуться с `BLOCKED`.**
- Гейт: `make check` **и** `make pre-commit-run` — CI гоняет второй первым, хук `typos`
  уже однажды уронил коммит на строке из теста.
- ruff `line-length = 100`, target py310; mypy strict по `src tests`.
- Осознанное упрощение — комментарий `# ponytail:` с потолком **и путём наверх**.

- Не коммить: коммит делает оркестратор.

## Что уже построено и переписыванию не подлежит

- `convert(skill_dir, source, target, *, root, out, scope, allow_stale) -> Conversion` —
  единственный шов. `Conversion(verdict, exit_code, report, summary)`.
- `refused(result, exit_code, message) -> Conversion` — держит отчёт, сводку и код процесса
  на одном числе; через неё проходят отказы 6, 7, 8, 11.
- `REFUSAL_VERDICT: dict[int, Verdict]` — явное «код отказа → вердикт».
- `EXIT_CODE = {clean: 0, lossy: 1, undecidable: 3}`, `UNREADABLE = 6`, `UNWRITABLE = 7`,
  `COLLISION = 8`, `REPORT_UNWRITABLE = 11`, `UNSTOPPED = (0, 1)`.
- `_frontmatter` превращает `_Anchored`, `yaml.YAMLError` и `RecursionError` в код 6.
- `_StrictLoader` отвергает якоря и алиасы; `SKILL_FILE_BYTES`, `FRONTMATTER_BYTES`,
  `FRONTMATTER_DEPTH`, `REQUIRED_FIELDS = ("description",)`.
- Сборка проверяет столкновения и выход за `--out` по всему плану до первой записи.

## Шов для тестов

`convert(...)` — один. Исключение одно и уже существует: тест через `CliRunner`
для того, что живёт вне шва (чистота stdout, `--report`, код процесса).

Тест, который может упасть только от переименования или переписывания текста,
писать не надо — ревью ловило такие четыре раза за прошлый прогон.

## Из таска 01 — граница отказа

- Граница `convert()` ловит `(ConvertError, OSError)`. Сторона решает код:
  чтение папки скилла — 6, сборка под `--out` — 7. Третьего кода не заведено.
- Проверка дублирующегося ключа переехала **после** `SafeConstructor.construct_mapping`:
  нехешируемый ключ приходит как `ConstructorError`, то есть код 6, а не `TypeError` наружу.
  Случай `unhashable-key` — в `BROKEN`.
- `_assemble` откатывает записанное при сорвавшемся копировании: `written == []`,
  файлов под `out` не остаётся. Пустые каталоги по пути остаются — помечено оговоркой.
- `advice` содержит строку и про бездомный файл верхнего уровня, не только про папку.
- Тест CLI пиннит `(piped.exit_code, saved.exit_code) == (0, 0)`.

## Из починки таска 01 — что ещё изменилось

- `OSError` при чтении **описаний** → код 3 («не знаем, что говорят среды»), не 6.
  Сообщение начинается с настоящего `error.filename`.
- Заголовок нормализуется при чтении: `date`/`datetime` → `isoformat()`, ключи тоже.
  `default=str` убран. Форма, у которой нет устойчивого текста (`!!set`, `!!binary`), —
  отказ кодом 6 из `_frontmatter`, независимо от `--out`.
- Каждое переписанное значение добавляет строку в `advice`: где, чем было, чем стало.
- Откат сборки: файлов не остаётся, пустой каркас каталогов назначения остаётся —
  решение записано в спецификации, `mkdir` не говорит, существовал ли каталог до нас.
- Строка 7 таблицы FR-27 покрывает оба случая кода 7.
