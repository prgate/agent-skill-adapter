# 03 — Три значения float, которых в JSON нет

**Требования:** R03 (находка ревью, открытая последним кругом по таску 01)
**Blocked by:** 01
**Зона:** `src/agent_skill_adapter/convert.py`, `tests/unit/test_convert.py`
**Волна:** 2
**Status:** ready

## Что должно заработать

Файл, который конвертер кладёт для целевой среды, остаётся валидным JSON при любом входе.

Сейчас не так: `hooks:\n  PreToolUse: .nan` даёт код 1 и кладёт в `hooks.json` голое `NaN`.
Строгий читатель такой файл отвергает — значит целевая среда получает то, что не JSON.
Проверено запуском.

## Почему это отдельный таск, а не третий дозапрос

Потолок в два дозапроса по таску 01 исчерпан, и он там не зря: каждый круг находил новое.
Находка при этом настоящая и стоит трёх имён в кортеже. Ticket вместо третьего круга —
чтобы правило осталось правилом.

## Из ревью, дословно

> «ветка `isinstance(value, (str, int, float))` пропускает три значения, которых в JSON нет:
> `hooks:\n  PreToolUse: .nan` даёт код 1 и кладёт в `hooks.json` голое `NaN` — проверил
> запуском, строгий читатель такой файл отвергает, то есть целевая среда получает файл,
> который не JSON · `nan`, `inf` и `-inf` должны стоять рядом с множеством и байтами
> в отказе — у них тоже нет текста, которым они пишутся; проверка, созданная ровно против
> форм без написания, пропускает их по типу.»

## Критерии приёмки

- [ ] `.nan`, `.inf` и `-.inf` в заголовке отвергаются тем же путём и тем же кодом 6,
      что множество и байты, — они попадают в ту же ветку, а не проходят по `isinstance`
- [ ] Обычные `int` и `float` по-прежнему проходят: правка сужает ровно три значения
- [ ] Случаи в таблице `BROKEN` рядом с `unstable-set` и `unstable-bytes`
- [ ] Тест краснеет без правки — покажи, чем именно
- [ ] `make check` и `make pre-commit-run` зелёные
