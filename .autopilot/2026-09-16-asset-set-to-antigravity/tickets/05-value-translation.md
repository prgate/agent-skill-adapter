# 05 — Перевод значений и имён инструментов, видимый в отчёте

**Требования:** R11, R12, R14, R17, R18, R48, R16, R47, R13, R11.1, R13.1
**Blocked by:** 04
**Зона:** `src/agent_skill_adapter/convert.py` · `tests/unit/test_convert.py` · `docs/adr/`
**Волна:** 4
**Status:** ready

## Что должно заработать

Значение поля, не входящее в закрытый набор целевой среды, переводится по таблице из файла
правил; переведённое видно в отчёте — что было, что стало, по какому правилу. Значение без
соответствия даёт строку отчёта, а не тишину. Имена инструментов переводятся тем же
механизмом; имя без документированной пары остаётся как есть и получает строку с причиной.
Решение «`opus` и `sonnet` → `pro`» записано в ADR одной строкой обоснования.

## Из брифа, дословно

> «Значение поля `model`, не входящее в закрытый набор целевой среды, переводится по таблице,
> а при отсутствии соответствия даёт строку отчёта, а не тишину.»
> «Каждое применённое правило видно в отчёте: что было, что стало, по какому правилу.»
> «Решение о значении принимается явно и записывается… выбранный должен быть обоснован
> одной строкой в ADR.»
> «Документация Antigravity называет `view_file`, `grep_search`, `run_command` и предупреждает,
> что неизвестное имя инструмента может подвесить субагента при вызове.»

## Разделы спецификации

Истории 7, 8, 10, 11, 23, 33–35; Решения §1, §2.

## Критерии приёмки

- [ ] Значение вне закрытого набора переводится по правилам; применённое правило попадает в отчёт строкой «было → стало, по правилу N»
- [ ] `opus` и `sonnet` дают `pro` в заголовке перенесённого субагента
- [ ] Значение вне набора и вне таблицы — строка отчёта с причиной, не тишина и не догадка
- [ ] У целевой среды набор значений не объявлен — перевод не применяется, строка отчёта говорит почему
- [ ] Значение `model` не строка — отказ с адресом: файл и поле названы
- [ ] Имя инструмента без документированной пары остаётся как есть и получает строку отчёта с советом
- [ ] Отчёт называет версию описаний **и** версию правил
- [ ] ADR: почему `opus` и `sonnet` оба в `pro` — одна строка обоснования
- [ ] `make check` зелёный
