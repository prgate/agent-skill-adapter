## Что должно заработать

**Субагенты собираются в назначение, которое называет описание цели (`agents.user` / `agents.project`),
с применённым переводом значений в заголовке.** Перевод посчитан таском 05 и отдан наружу готовым
(`Assessed.translations`: `path`, `id`, `from`, `to`, `rule`) — остаётся записать его в заголовок
собираемого файла. Без этого шага весь трек не закрывается: приёмка требует, чтобы среда назвала
каждое имя входного набора, а невидимость субагентов — ровно та проблема, ради которой всё затевалось.

Файлы правил ложатся в `.agents/rules/` — туда, куда указывает запись `rules.project`
описания цели, а не туда, где их не читает ничто. Команды не переносятся вовсе: записи
`commands.*` в описании цели нет, и каждая команда набора получает строку отказа с причиной
и единственной известной заменой.

## Критерии приёмки

- [ ] Каждый субагент набора собирается в назначение, которое называет описание цели; ни один путь не вписан в код
- [ ] В заголовке собранного субагента стоит переведённое значение — `opus` и `sonnet` дают `pro`. Это приёмка 34 спецификации и история 7: она не закрывается ничем другим в плане
- [ ] Имена инструментов в собранном файле — переведённые там, где пара документирована; непарные остались как были, и про каждое есть строка отчёта (она уже есть с таска 05 — проверить, что не потерялась при сборке)
- [ ] Каждый файл правил набора попадает в назначение записи `rules.project`; ни один путь не вписан в код
- [ ] У переложенного файла правил есть заголовок `trigger: always_on` — без него среда его не читает (D01, проверено запуском). Значение берётся из набора, объявленного в описании среды; сам заголовок добавляется по правилу из файла правил перевода. Ни то, ни другое не вписано в код
- [ ] Файл, у которого заголовок уже есть, не переписывается — добавляется только недостающее
- [ ] В описании Antigravity появляется запись про заголовок правила с закрытым набором значений и источником — поставляемый с CLI `agy-customizations` (`Only \`always_on\` rules are loaded unconditionally`)
- [ ] Ни одного файла команд в перечне записанного — ни при каком назначении
- [ ] На каждую команду набора — строка отказа: что это, почему не переносится, что делать руками
- [ ] Число строк отказа равно числу команд на входе; пустая папка команд даёт ноль строк
- [ ] **Правило по недокументированному файлу исполняется, а не только объявляется.** `action: copy|skip` из файла правил решает судьбу каждого такого файла при сборке; строка отчёта у него уже есть с таска 04. Без этого `action` остаётся декларацией: ни один таск его до сих пор не брал
- [ ] Два файла правил с одинаковым именем из разных папок входа — отказ с кодом коллизии, а не победа последнего
- [ ] `make check` зелёный
