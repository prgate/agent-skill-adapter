# Agent Skill Adapter

[In English](README.en.md)

**Говорит, что теряет скилл при переносе в другую агентную среду — до того, как вы его перенесли.**

Сам файл скилла переносится легко. Гарантии вокруг него — нет. Открытая спецификация
Agent Skills требует двух полей; Claude Code добавляет к ним восемнадцать своих, плюс
субагентов с их правами и лимитами, плюс hooks. Другая среда открывает такой скилл, молча
пропускает всё, чего не знает, и запускается.

Файл прочитан, поведение изменилось. Пропадают не украшения: скилл больше не работает в
отдельном контексте, набор инструментов агента не ограничен, проверки до и после вызова
инструмента не выполняются, а разделение «запускает только человек» и «запускает только
модель» исчезает. Скилл с побочными эффектами — тот, что умеет коммитить или деплоить, —
после такого переноса становится опаснее оригинала.

Адаптер отвечает, что переживёт перенос, а что нет — по документации самих поставщиков, а
не по памяти.

## Как это работает

![Как адаптер превращает документацию поставщиков в перечень пробелов](docs/assets/how-it-works.svg)

**Описание среды** — YAML-файл о том, что среда документирует про себя. У каждой записи
указан раздел документации, откуда она взята: ссылка, якорь и sha256 нормализованного
текста этого раздела. Поэтому утверждение можно проследить, а изменение на странице
поставщика — обнаружить, а не предположить.

Два описания сравниваются запись за записью. Результат — **перечень пробелов**: что целевая
среда говорит о каждой возможности, которая есть у исходной.

Три правила решают, как читается перечень:

- **Молчание — не отказ.** `missing` оставлен для отказа, который поставщик написал словами.
  Документация, которая ничего не говорит, — это `unknown`, и записи, которых у цели нет
  вовсе, считаются отдельно от тех, что есть, но без вердикта.
- **Отсутствие — не поддержка.** Возможность, записи о которой нет, считается неизвестной,
  а не поддержанной.
- **При сомнении — отказ.** Описание с записанным расхождением или проверенное давнее
  объявленного срока считается устаревшим и не выдаётся. Версия вне всех объявленных
  диапазонов отвергается, а не сводится к ближайшему описанию.

Сравнение не обращается в сеть и на одних и тех же входных данных даёт тот же результат
до байта. В сеть ходит только сверка с документацией.

## Что он говорит сегодня

Claude Code 2.1 → Google Antigravity 2.0, по документации, проверенной 14.09.2026:

| Исход | Записей | Из них цель не имеет записи вовсе |
|---|---|---|
| воспроизводится | 22 | 0 |
| не поддерживает | 0 | 0 |
| неизвестно | 70 | 8 |
| вне переноса | 3 | — |

Antigravity документирует 2 из 20 полей frontmatter скилла Claude Code, 3 из 33 событий
hooks и 7 из 19 полей субагента. Ноль в «не поддерживает» — потому что ни на одной из 91
страницы своей документации Antigravity не отказывает словами: она перечисляет, что умеет,
и молчит про остальное.

Это различие и есть смысл перечня. Продолжать проект оправдано тем, что документация
молчит, а не тем, что среда чего-то не умеет.

Полный перечень: [`specs/gaps/claude-code-to-antigravity.md`](specs/gaps/claude-code-to-antigravity.md).

## Что уже есть, а чего ещё нет

**Конвертации пока нет.** Сегодня инструмент отвечает на один вопрос — что именно теряется
при переносе — и не переносит ни одного файла. PRD требует получить этот ответ **до** работ
над ядром: если бы непереносимого не оказалось, продукт свёлся бы к копированию файлов и
делать его было бы незачем.

Что работает:

- описания двух сред, где каждая запись привязана к разделу документации ссылкой, якорем и
  хешем;
- загрузчик: выбор описания по версии среды, отказ на устаревшем и на неоднозначном;
- сверка с документацией поставщика и запись расхождения в сам файл описания;
- вычисляемый перечень пробелов.

Чего ещё нет: чтения репозитория со скиллами, оценки переноса каждого свойства, отчёта о
переносе, переписывания текста скилла под целевую среду, сборки результата и кодов
возврата. Это блоки B–F [PRD-001](docs/prd/PRD-001-agent-skill-adapter.md).

## Быстрый старт

Нужны Python 3.10+ и [uv](https://github.com/astral-sh/uv).

```bash
git clone git@github.com:prgate/agent-skill-adapter.git
cd agent-skill-adapter
make install
```

Пересобрать перечень пробелов из описаний в `specs/`:

```bash
uv run python -m agent_skill_adapter.envspec.gaps
```

Команда пишет `specs/gaps/claude-code-to-antigravity.md` и `.json`. Те же входные данные —
те же байты: повторный запуск, которому нечего менять, файлы не трогает. Ненулевой код
возврата означает, что не осталось ни `missing`, ни `unknown`, — то есть перенос сводится к
копированию файлов и этот инструмент не нужен.

Спросить описание напрямую:

```bash
uv run python - <<'PY'
from agent_skill_adapter.envspec.loader import select, capability

spec = select("specs", "anthropic", "claude-code", "2.1.270")
print(spec.environment, spec.version_range, spec.checked_at)
print(capability(spec, "skill.frontmatter.allowed-tools"))
PY
```

Проверить, не сдвинулась ли документация поставщиков с тех пор, как написаны описания, —
единственная команда, которой нужна сеть:

```bash
uv run python -m agent_skill_adapter.envspec.freshness            # только отчёт
uv run python -m agent_skill_adapter.envspec.freshness --write    # записать найденное
```

Изменившийся раздел, недоступная страница или исчезнувший якорь записываются в сам файл
описания — чтобы локальный запуск без сети видел устаревание по файлу, а не по журналу CI.

## Чего он не делает

- **Не устанавливает.** Разложить файлы по папкам сред умеет `npx skills`; адаптер готовит
  результат в стандартном виде и отдаёт его.
- **Не сочиняет скиллы.** Замысел — переносить существующие.
- **Не проверяет поведение на живой модели.** Совпало ли поведение — это отдельные платные
  прогоны, и они сознательно не смешаны с разбором переноса.

Направление одно: Claude Code → Google Antigravity. На вход задуман репозиторий целиком —
отдельный скилл без репозитория пока не рассматривается.
